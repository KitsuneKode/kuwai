Findings: (1) “Reply all” and “preview all” are not absent from the UI by accident — the pipeline never loads Cc, prior messages, or PR diffs. (2) Conversation threads collapse to one card via groupKey; history lives in Gmail/GitHub, not in notifications.json. (3) GitHub “Reply” is always a new issue comment, not an inline reply to one person in a mail sense. (4) Review requests peek but intentionally omit Reply until you add an API (approve/request changes). (5) Sensible product split: Tier 1 expand in center + notch dwell (cheap); Tier 2 thread sheet (feeds work); Tier 3 reply-all / approve (explicit scope).
